## 0. 文体規定（暫定デフォルト・ぶりちゃん確認待ち）

- **長さ**: 各軸2文（結論1文＋理由or注意1文）
- **断定度**: 「〜しやすい」「〜に向く」のソフト断定（旺相休囚係数の導入後、旺相時のみ言い切りに格上げ可）
- **凶方位の使い道**: 採用（「死門=ダメ」でなく「△△には不向き、◯◯なら向く」）。初心者混乱対策として、総合ランクのアイコン（◎○△▲×）を必ず先頭に置き、使い道は2文目に回す
- **健康軸**: 医療的断定の禁止。「通院・検診・静養に向く方位」の枠を超えない
- **構成**: 結論ファースト → 理由ひとかけら → 注意は最大1個

## 1. 判定階層（宮ごとに上から評価、上位が下位を上書き）

### Level 0: 盤全体の拒否権（ban_level カラム）
| 条件 | 判定 | 例外 |
|---|---|---|
| 伏吟 | 全体凶（吉星吉門あっても覆らない） | 金運軸のみ「財の整理・貯蓄」は可（惟宜収斂貨財） |

```

  → Level 0〜5 判定 → 判定オブジェクト {rank, vetoes[], gate, gateForce, star, starRank, god, shouiTop[]}
  → 文言バンク（パターン別テンプレ×3〜5バリエ）に流し込み
  → 1080 × 8 × 5軸 = 43,200 エントリのJSON（ビルド時生成・静的同梱）

```

## 追補（PR-V1 / 2026-08）

### 三大凶格の定義と拒否権
`shoui_dict.json` の kakkyoku 配列で説明文に「三大凶格」を含むのは
伏宮格 / 飛宮格 / 戦格 の3件。これらを Level 1 拒否権に追加した。

上表の凶格マッピングでは伏宮/飛宮を「勝負×（仕事軸のみ）」としていたが、
象意文の内容（生命の危機・重大な決断は延期・安全と健康を最優先）に基づき
**全軸×の拒否権**に格上げした。上表よりこの追補が優先する。

### 未解決（PR-V1 の対象外）
- 順利ボーナス(+20)が凶格の有無を判定していない。
  `detectJunri()` は「吉門4種 + score>=40」の2条件のみで、
  凶格が出ている宮ほど条件を満たしやすく加点されやすい逆説的構造。
  `src/kimon/junri.js`（聖域）のため今回は未修正。スコア数値には拒否権が及ばない。
- 「大吉」の閾値がトーン系統間で不一致（getBadge `>=60` / getScoreTone `>=40`）。
- 吉方位タブ側（L2/L3/地図）に凶格の警告表示自体が存在しない（PR-V2 で対応予定）。
- `strongestRanking.js` の `BAD_BREAKDOWN_KEYS` に
  `kakkyoku` / `jukkan_kokuou` が含まれていない（PR-V3 で対応予定）。
